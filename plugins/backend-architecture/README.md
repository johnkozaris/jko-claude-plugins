# Backend Architecture

A small, cross-stack skill for consequential backend architecture decisions.
It supplies a few production-tested opinions while leaving framework knowledge
and implementation details to the model, the repository, and current primary
documentation.

Use it for service boundaries, modular-monolith versus microservice decisions,
data ownership, transport choices, and production topology. Do not use it as a
general backend coding handbook.

The optional `production-shapes.md` reference compares architectural shapes by
ownership, consistency, failure, and operational cost.
